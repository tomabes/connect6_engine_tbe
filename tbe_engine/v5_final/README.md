## Method

1. **Self-play.** Games start from random openings near the centre, using
   6 processes and half the time budget. In each **quiet** position (neither
   side has 4–5 stones in a six-cell window), the teacher — a search over one
   full move + quiescence with manual weights — provides an exact score,
   which serves as the label. During the first 6 moves, with probability 0.3,
   a different move from the top 4 is played instead of the best move to
   increase position diversity.
2. **Weight tuning** (bootstrapping from search, as in TD-Leaf / Texel tuning).
   The static evaluation `E = Σ w·(black_feature − white_feature)` is trained
   to predict the teacher's score: both pass through a sigmoid with scale K
   (the median |teacher score|), using logistic loss, Adam, and early stopping
   on validation data (20 % of games). The trainable weights are
   `line_1, line_2, line_3, connectivity`; `line_4, line_5, threat_1..3` are zero
   in quiet positions and their weights remain fixed. Weights are bounded
   between ¼ and 3.5–4× the manual values, with
   `line_1 < line_2 < line_3 < line_4`. The side-to-move term (tempo) is used
   only during training: at a fixed depth, it does not change move selection.
   The baseline uses manual weights.
3. **Evaluation matches.** Learned weights against manual weights:
   12 new openings × 2 colours, 3 seconds per move, with a 40-move limit
   resulting in a draw.
4. **Selection.** Learned weights are accepted if validation loss is lower
   AND they score > 50 % of the points in the evaluation matches. Otherwise,
   manual weights are retained. The result is stored in `learned_weights.json`.

## Experiment with a naive initialisation

A check that the training procedure finds reasonable weights on its own.
Initial values: `line_1, line_2, line_3 = 1, 2, 3` (weight = number of stones),
`connectivity = 1`; tactical weights (`line_4, line_5`, threats) are the same
as the manual weights. L2 regularisation pulls towards the initial weights,
not the manual ones, to avoid supplying the answer. Evaluation matches compare
the learned weights against the naive initial weights.

## Manual weights

Set during v3 development (`defines.py`, `EVAL_WEIGHTS`): line weights
1, 4, 16, 64, 256 — each additional stone in a window is worth 4 times more;
threat weights 600 / 3000 / 15000 according to the number of stones needed
for defence (Wu & Huang); connectivity weight 2 (Liu Yung-ching's idea).
